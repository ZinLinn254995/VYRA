VYRA · TECHNICAL OVERVIEW

VYRAL DNA: portable identity for creative assets.

A Vyral is a reusable collection of creative assets and their identity records. The .vyral package is designed to carry those records between workspaces, while DNA and fingerprints serve different purposes: reconstruction and verification.

What does VYRAL DNA describe?

Asset DNA records the data needed to identify and recover supported asset content. A VYRAL package can include a manifest, asset metadata, DNA records and the lossless payload required by the supported reconstruction method. It is not just a text description or a prompt.

Two reconstruction paths

Raster images: exact decoded samples

For supported PNG, JPEG and WebP uploads, VYRA uses a pinned server-side ImageMagick WASM decoder to produce a canonical row-major RGBA8 sample stream. The stream is stored in lossless tiles. Tile SHA-256 values and an aggregate decoded-sample SHA-256 digest are checked during reconstruction.

Important boundary: this path can recover the decoded pixel samples exactly under the recorded decoder contract and encode them into a new PNG. It does not recover the original PNG or JPEG file bytes, original compression choices, or every original metadata chunk.

Other files: exact source bytes

For supported non-raster files, File DNA v1 records the source file's SHA-256 identity and can carry lossless source-byte chunks in a DNA-only package. When every chunk and the aggregate digest pass verification, the original binary bytes can be reconstructed exactly.

DNA and fingerprints are not the same

  • DNA describes the supported structure or content needed for reconstruction.
  • Fingerprint checks whether bytes or decoded samples match a recorded identity.
  • Provenance records where an asset or observation came from and whether its claims are trusted.

A matching fingerprint is evidence of identity for the data that was hashed. It does not, by itself, prove authorship, ownership, copyright or a license grant.

Can an AI assistant use a VYRAL package?

The portable ZIP-compatible .vyral format is intended to make asset identity records inspectable by compatible tools. An AI assistant can only reconstruct what is actually present in the package and what its tools support. Descriptive text alone cannot recreate missing source bytes or guarantee an identical image.

Third-party access to private VYRA assets requires explicit, permission-controlled access. Exporting a package and granting an external service ongoing access are separate actions; a package does not silently grant account access.

Current capability and limitations

VYRA's asset DNA and package workflows are evolving. Current raster extraction supports PNG, JPEG and WebP within configured upload and image-size limits. Other file types use deterministic file identity records; exact reconstruction requires a DNA-only package containing the lossless byte payload. Imported verification claims are treated as unverified evidence until checked again in the destination workspace.
